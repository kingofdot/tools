# MSDS → 관리요령 게시물 제작 지침 (상세판)

MSDS(물질안전보건자료) PDF 한 장을 입력받아, 작업장에 게시하는 **「물질안전보건자료대상물질의 관리요령」 1페이지 게시물**을 **PDF + JPG 두 형식**으로 자동 생성하는 방법을 처음부터 끝까지 설명한다.

이 문서만 그대로 따라 하면 (사람이든 AI든) 동일한 결과물을 만들 수 있도록 작성했다. 중간에 막히는 지점(특히 "왜 자꾸 2페이지가 되지?")까지 원인과 해결책을 적어 두었다.

---

## 0. 결과물 미리보기

- 상단 큰 제목: **물질안전보건자료대상물질의 관리요령**
- 그 아래 2열 표. 왼쪽은 항목 라벨(회색 칸), 오른쪽은 내용.
- 표 항목 순서: **제품명 → 그림문자 → 신호어 → 유해성·위험성 → 취급상의 주의사항 → 적절한 보호구 → 응급조치 요령 및 사고 시 대처방법**
- 전체가 **A4 한 페이지**에 들어가야 한다(JPG는 한 장 이미지라 1페이지가 필수다).

---

## 1. 준비물 (실행 환경)

- **Windows + 한글판 Microsoft Word 설치** (docx → PDF 변환에 Word COM을 쓴다. 없으면 LibreOffice로 대체 가능 — 8절 참고)
- **Python 3.9+**
- 파이썬 패키지 3개:

```bash
pip install python-docx PyMuPDF pywin32
```

| 패키지 | 용도 |
|---|---|
| `python-docx` | 워드(.docx) 표/문서 생성 |
| `PyMuPDF` (import 이름 `fitz`) | 원본 PDF에서 그림문자 아이콘 추출, 최종 PDF를 JPG로 렌더 |
| `pywin32` | (선택) Word COM 자동화. PowerShell로 대신해도 됨 |

- **참조용 워드 템플릿 하나**(글꼴/여백이 잡힌 빈 워드). 없으면 스크립트가 새 문서를 만들어도 된다. 이 지침의 스크립트는 템플릿 없이도 동작하도록 되어 있다.

## 2. 입력: MSDS PDF의 구조 이해

한국 MSDS는 법정 16개 항목으로 구성된다. 관리요령에 필요한 부분만 추리면 다음과 같다.

| MSDS 위치 | 내용 |
|---|---|
| `1. 화학제품과 회사에 관한 정보` → `가. 제품명` | 제품명 |
| `2. 유해성·위험성` → `가. 유해성·위험성 분류` | 구분 목록(인화성 액체 구분2 등) |
| `2. 유해성·위험성` → `나. 예방조치 문구를 포함한 경고 표지 항목` | 그림문자(아이콘), 신호어, 유해·위험 문구(H코드) |
| `4. 응급조치 요령` → `가.~마.` | 눈/피부/흡입/먹었을 때/기타 |
| `7. 취급 및 저장 방법` → `가. 안전취급요령` | 취급상의 주의사항 |
| `8. 노출방지 및 개인보호구` → `다. 개인 보호구` | 호흡기/눈/손/신체 보호구 |

> ⚠️ **중요한 함정:** MSDS PDF에서 텍스트를 추출하면 **줄 순서가 뒤죽박죽**으로 나온다(항목 라벨과 값이 멀리 떨어져 나오거나, 뒤 페이지 내용이 먼저 나오기도 한다). 그래서 "텍스트만 긁어서 자동 매핑"하면 반드시 틀린다. **반드시 PDF를 눈으로(또는 페이지 이미지로) 보면서 각 값을 정확한 항목에 손으로 매핑**해야 한다. AI에게 시킬 때도 "페이지 이미지를 보고 매핑하라"고 지시할 것.

## 3. 그림문자(GHS 픽토그램) 확보 방법 — 핵심

그림문자는 직접 그리지 말고 **원본 MSDS PDF에 이미 박혀 있는 아이콘 이미지를 그대로 추출**한다. 그게 가장 정확하고 빠르다.

```python
import fitz, os
src = r"원본MSDS.pdf"
d = fitz.open(src)
page = d[0]                      # 보통 그림문자는 1페이지 "2.나"에 있음
os.makedirs("ghs_raw", exist_ok=True)
for i, im in enumerate(page.get_images(full=True)):
    xref = im[0]
    pix = fitz.Pixmap(d, xref)
    if pix.n > 4:                # CMYK 등은 RGB로 변환
        pix = fitz.Pixmap(fitz.csRGB, pix)
    pix.save(f"ghs_raw/img{i}_{pix.width}x{pix.height}.png")
    print(i, pix.width, "x", pix.height)
```

- 추출된 이미지 중 **빨간 마름모(다이아몬드) 안에 검은 심볼**이 그림문자다. 회사 로고 같은 다른 이미지도 같이 나오므로 눈으로 골라낸다.
- GHS 픽토그램 종류(참고): 화염(GHS02·인화성), 느낌표(GHS07·경고), 건강유해성 사람 실루엣(GHS08), 가스실린더(GHS04·고압가스), 해골(GHS06·급성독성), 부식(GHS05), 폭발(GHS01), 원형 화염(GHS03·산화성), 환경(GHS09).
- **MSDS에 그려진 순서대로** 배치한다.
- 골라낸 파일을 `ghs/` 폴더에 알아보기 쉬운 이름으로 복사해 둔다.

### 표시 규칙
- **크기: 34px × 34px로 통일**, 셀 **가운데 정렬**.
- 워드에 넣을 때는 원본(예: 81×80)을 그대로 넣되 **표시 크기만 34px로 지정**한다(미리 34px로 줄여 저장하면 오히려 흐려질 수 있음).
- 34px = 34/96 인치. `python-docx`에서 `Inches(34/96)`.

## 4. 신호어 규칙

- MSDS `2.나. 신호어` 값을 그대로: **`위험`** 또는 **`경고`** 중 하나.
- 값이 없거나 빈칸이면 **`해당없음`**으로 표기한다.
- 위치는 표에서 그림문자 바로 아래 행.

## 5. 디자인/스타일 스펙

- 글꼴: **맑은 고딕**
- **모든 글씨는 검은색(000000).** 제목·라벨·본문 전부. 색은 표 라벨칸 음영(연회색)과 테두리에만 쓴다.
- 표 스타일: 라벨열(왼쪽) 연회색 `F2F2F2` 음영, 바깥·안쪽 얇은 검정/회색 테두리.
- 제목: 14pt 굵게, 가운데.
- 본문: 7.8~8.2pt(1페이지에 맞추려 작게), 줄간격 0.97.
- **유해성·위험성 칸은 "분류 | 유해·위험 문구"를 좌우 2단(중첩표, 테두리 없음)으로** 배치한다. 세로로 길게 나열하면 페이지를 넘기므로, 2단으로 접어 높이를 반으로 줄이는 게 핵심이다.
- 적절한 보호구는 `[호흡기 보호] [눈 보호] [손 보호] [신체 보호]` 소제목으로 묶는다.
- 응급조치는 `가.~마.` 소제목 + 각 항목 한두 줄.

## 6. 1페이지에 맞추는 노하우 (삽질 방지)

이 작업에서 가장 애먹는 부분. 아래를 지키면 1페이지로 확정된다.

1. **표 맨 뒤 트레일링 단락 주의.** 표가 문서 마지막 요소면 워드가 뒤에 빈 단락(약 11pt)을 자동으로 붙이는데, 이게 페이지를 넘긴다. → 스크립트에서 **1pt짜리 빈 꼬리 단락을 직접 추가**해 높이를 죽인다.
2. **`cantSplit`(행 나눔 금지)를 켜지 말 것.** 큰 행(응급조치 등)에 `cantSplit`을 걸면 그 행이 통째로 다음 장으로 밀려 오히려 2페이지가 된다. 1페이지가 목표면 끄는 게 맞다.
3. **여백을 줄인다.** 위 0.6cm / 아래 0.5cm / 좌우 1.2cm 정도.
4. **폰트·줄간격 압축.** 본문 7.8~8.2pt, 줄간격 0.97, 문단 간격 0.1~0.2pt.
5. **유해성 2단 배치**(5절)로 세로 길이 절감.
6. 검수: PyMuPDF로 **페이지 수가 1인지** 확인하고, 페이지의 텍스트 최대 y좌표가 여백 안(예: 770 / 841)인지 본다.

```python
import fitz
d = fitz.open("결과.pdf")
print("pages", d.page_count)                    # 1 이어야 함
p = d[0]
ys = [b[3] for b in p.get_text("blocks") if b[4].strip()]
print("max_y", max(ys), "/", p.rect.height)     # max_y가 페이지 높이보다 충분히 작아야
```

## 7. docx → PDF → JPG 변환

### 7-1. docx → PDF (Word COM, PowerShell)
> OneDrive 경로에서 **한 Word 인스턴스로 여러 파일을 연속 변환하면** "파일을 찾을 수 없습니다 / RPC" 오류가 난다. **파일 1개당 새 인스턴스**로 처리할 것.

```powershell
$src = "C:\경로\관리요령.docx"
$pdf = "C:\경로\관리요령.pdf"
$w = New-Object -ComObject Word.Application
$w.Visible = $false
$d = $w.Documents.Open($src)
$d.ExportAsFixedFormat($pdf, 17)   # 17 = PDF
$d.Close($false)
$w.Quit()
```

### 7-2. PDF → JPG (PyMuPDF)
```python
import fitz
d = fitz.open("관리요령.pdf")
d[0].get_pixmap(dpi=200).save("관리요령.jpg")   # 확장자로 JPEG 저장
```

- 최종 저장물은 **PDF + JPG 두 개**. (중간 산출물 docx는 지워도 됨.)

## 10. AI(제미나이/GPT 등)에게 시킬 때 프롬프트 예시

> 아래 MSDS PDF를 첨부한다. **페이지 이미지를 직접 보고** 다음을 추출해 `CONFIG` 값으로 채운 뒤, 첨부한 `make_gwanri.py`를 실행해 관리요령 docx를 만들고, Word로 PDF, PyMuPDF로 JPG(200dpi)까지 만들어라.
> - 제품명 = 1.가
> - 그림문자 = 2.나의 아이콘들(PDF에 임베드된 이미지를 `get_images`로 추출, 표시 순서 유지, 34px)
> - 신호어 = 2.나(위험/경고, 없으면 해당없음)
> - 유해성·위험성 = 2.가 분류 + 2.나 H문구
> - 취급상의 주의사항 = 7.가
> - 적절한 보호구 = 8.다
> - 응급조치 = 4.가~마
> - 결과물은 **A4 1페이지**여야 하며, PDF+JPG 두 개로 저장한다. 페이지 수가 1인지 PyMuPDF로 검증하라.

AI가 자꾸 2페이지를 만들면 6절(트레일링 단락 1pt, cantSplit 끄기, 유해성 2단, 여백/폰트 축소)을 지시하라.

## 12. 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| 자꾸 2페이지가 됨 | 표 뒤 자동 빈 단락 / 큰 행이 통째로 밀림 | 1pt 꼬리 단락 추가, `cantSplit` 끄기, 유해성 2단, 여백·폰트 축소 |
| Word 변환 시 "파일을 찾을 수 없습니다/RPC" | 한 인스턴스로 여러 파일 연속 변환(특히 OneDrive 경로) | 파일 1개당 새 Word 인스턴스 |
| 그림문자가 흐림 | 34px로 미리 줄여 저장 후 다시 삽입 | 원본 해상도를 넣고 표시 크기만 34px 지정 |
| 값이 엉뚱한 항목에 들어감 | MSDS 텍스트 추출 순서가 뒤섞임 | 페이지 이미지를 보며 손으로 매핑 |

| docx→PDF 불가 | Word 미설치 | LibreOffice `soffice --headless --convert-to pdf` (8절) |
