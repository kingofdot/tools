## 1. 쓸자료/별표/ 데이터 패치

### 1-1. 시행령 별표3 처리시설 종류 (6건)

대상: [`쓸자료/별표/시행령/별표3_처리시설종류.json`](../쓸자료/별표/시행령/별표3_처리시설종류.json)

**A. 잘못된 항목 분할 병합 (1건):**

OLD parser 가 `(가-하))` 인라인 분할로 "익히는 것)" 의 "것)" 를 마커로 오인식해 1개 항목을 2개로 쪼갠 케이스.

| index | Before | After |
|---:|---|---|
| 50 | `가)` `부숙(썩혀서 익히는` | `가)` `부숙(썩혀서 익히는 것) 시설(미생물을 이용하여 유기물질을 발효하는 등의 과정을 거쳐 제품의 원료 등을 만드는 시설을 말하며, 1일 재활용능력이 100킬로그램 이상 200킬로그램 미만인 음식물류 폐기물 부숙시설은 제외한다)` |
| 51 | `것)` `시설(미생물을 이용하여 …)` | (제거) |

**B. 80컬럼 wrap 결합 시 공백 누락 (5건):**

| index | marker | 수정 |
|---:|---|---|
| 20 | `2)` | `이용하여폐기물을` → `이용하여 폐기물을` |
| 25 | `마.` | `있다고인정하여` → `있다고 인정하여` |
| 30 | `나.` | `있다고인정하여` → `있다고 인정하여` |
| 45 | `2)` | `이용하여폐기물을` → `이용하여 폐기물을` |
| 50 | `가)` | `발효하는등의` → `발효하는 등의` / `부숙시설은제외한다` → `부숙시설은 제외한다` (병합 시 함께 적용) |

### 1-2. 시행규칙 별표1·별표4 fragment 패턴 (2건)

대상: [`쓸자료/별표/시행규칙/별표1_지정폐기물유해물질함유기준.json`](../쓸자료/별표/시행규칙/별표1_지정폐기물유해물질함유기준.json), [`쓸자료/별표/시행규칙/별표4_폐기물세부분류코드.json`](../쓸자료/별표/시행규칙/별표4_폐기물세부분류코드.json)

OLD parser 가 80컬럼 wrap 으로 다음 줄에 떨어진 닫는 괄호 fragment(`다)` 만 단독)를 처리하지 못해, 그 다음 진짜 마커("나.", "06-01-04") 의 본문이 fragment 항목에 들어간 케이스.

| 파일 | index | Before | After |
|---|---:|---|---|
| 별표1 | 16 | `가.` `…해당한` | `가.` `…해당한다)` |
| 별표1 | 17 | `다)` `나. 석면(…)` | `나.` `석면(…)` |
| 별표4 | 88 | `06-01-03` `…말한` | `06-01-03` `…말한다)` |
| 별표4 | 89 | `다)` `06-01-04 폐연료유` | `06-01-04` `폐연료유` |

## 2. `tools/law_api.py` parser 보강

향후 API 재조회 시 동일 패턴이 재발하지 않도록 다음 보강 적용:

### 2-1. `split_inline_markers` — 한글 letter marker 인라인 분할 제거

```python
# 제거됨:
# s = re.sub(r"\s+(\([가-하]\))\s+", r"\n\1 ", s)
# s = re.sub(r"\s+([가-하]\))\s+", r"\n\1 ", s)
```

본문에 자연스럽게 등장하는 "이라 한다)", "익히는 것)" 등을 마커로 오인식하던 문제 해결. 줄 시작에서의 마커 인식은 `build_appendix_items` 가 담당하므로 인라인 분할이 불필요.

### 2-2. `process_text_segment` — fragment 휴리스틱 추가

```python
_FRAGMENT_RE = re.compile(r"^(?:[가-하]\)|[0-9]+\)|\([가-하]\)|\([0-9]+\))$")
# 본문이 없는 단순 마커 패턴은 80컬럼 wrap fragment 로 보고 이전 줄 끝에 결합
if _FRAGMENT_RE.match(stripped):
    lines[-1] = re.sub(r"\s+", " ", f"{lines[-1]}{stripped}").strip()
    continue
```

"해당한" + "다)" + "나. 석면…" 같은 raw 분할이 자동으로 "해당한다)" + "나. 석면…" 로 정정됨.

### 2-3. `_BROKEN_WORD_PAIRS` — 알려진 공백 누락 패턴 사전 추가

```python
("하여폐기물", "하여 폐기물"),
("있다고인정", "있다고 인정"),
("하는등의", "하는 등의"),
("시설은제외", "시설은 제외"),
```

80컬럼 wrap 단어경계 결합 시 공백 누락 케이스를 사후 보정. 일반 휴리스틱(한글-한글 인접 시 공백 삽입)은 false positive 위험으로 미적용. 보수적으로 발견된 케이스만 사전 등재.
