# terms-review — 약관 검토 작업장

약관 초안을 받아 (1) 데이터화 → (2) 법령정보센터에서 인용 검증·수정 →
(3) 워드 내보내기 까지의 작업 자료를 보관합니다.

## 폴더 구조

| 경로         | 용도                                              |
|--------------|---------------------------------------------------|
| `drafts/`    | 사용자가 주는 약관 초안(.txt / .md / 붙여넣은 텍스트) |
| `data/`      | 1단계 — 초안을 JSON 으로 데이터화한 결과          |
| `sources/`   | 2단계 — 법령정보센터에서 받아온 검증 자료(법조문 발췌 .md) |
| `reviewed/`  | 2단계 결과 — 인용 오류·문언 정밀화를 반영한 최종 JSON     |

## 워크플로우

1. **초안 → 데이터화**
   - `drafts/<이름>.txt` 에 원문 보관
   - 약관을 조항/항/호 단위로 분해해 `data/<이름>.json` 생성
   - 스키마 (예시):
     ```json
     {
       "title": "이용약관",
       "articles": [
         {
           "no": 11,
           "title": "청약철회 및 환불",
           "paragraphs": [
             {
               "no": 1,
               "text": "회원은 「전자상거래…법」 제17조에 따라 …",
               "citations": [
                 { "law": "전자상거래 등에서의 소비자보호에 관한 법률",
                   "article": "17", "paragraph": 1 }
               ],
               "items": [ { "no": 1, "text": "…" }, … ]
             }
           ]
         }
       ]
     }
     ```

2. **법령정보센터 확인 → 수정**
   - `data/*.json` 의 모든 `citations` 를 law.go.kr 에서 직접 조회
   - 인용 조문 발췌를 `sources/<법령명>__<조>.md` 에 저장
   - 인용 오류·문언 부정확을 정리해 `reviewed/<이름>.json` 생성
   - 수정 사유는 같은 JSON 내 `reviewNotes[]` 에 기록

3. **워드 내보내기** *(추후 작업)*
   - `reviewed/*.json` → `document-builder` 의 blocks 스키마로 변환
   - document-builder 에서 import 후 워드 생성

## 사용 흐름

- 사용자가 채팅에 약관 초안을 붙여넣거나 `drafts/` 에 직접 둠
- 어시스턴트가 1·2단계를 수행하고 결과를 위 위치에 저장
- 진행 상황·검토 의견은 conversation 으로 보고
