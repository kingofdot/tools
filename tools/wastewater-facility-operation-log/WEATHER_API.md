# 날씨와 온도 연동 가이드 (기상청 apihub 기후통계, 개발자 인수인계)

폐수배출시설 운영일지 생성기(`index.html`)의 **날씨와 온도 자동 채우기** 기능을 기상청 API와 연동하는 문서입니다.
**온도와 날씨 모두 구현 완료** 상태이며, 데이터 소스는 **기상청 기후통계 일자료(sts_\*)** 입니다. 배포 시 개발자가 마무리할 항목은 §8에 정리했습니다.

---

## 0. 요약 (TL;DR)

| 항목 | 현황 |
|---|---|
| 온도 | 구현 완료. `sts_ta`(기온 기후통계)의 일평균기온 사용 |
| 날씨 | 구현 완료. `sts_cloud`/`sts_rn`/`sts_sd`/`sts_fog`로 맑음/흐림/비/눈/안개 산출 |
| 호출 수 | **기간당 5회**(요소별 1회, 날짜 수와 무관). 일자료라 한 번에 기간 전체가 옴 |
| CORS | apihub는 CORS 헤더가 없어 브라우저 직접 호출 불가 → 로컬 프록시(`kma_proxy.py`)가 우회 |
| 배포 | 로컬 프록시를 **서버 프록시**로 이전 + authKey 교체 (§8) |

- **인증키(authKey):** `wiEQCJ__QkmhEAif_wJJtQ`
- **관측지점:** 기본 `203`(이천). 드롭박스에서 60여 개 ASOS 지점 선택.
- **중요:** 기후통계 API의 지점 파라미터는 `stn` 이 아니라 **`stn_id`**, 날짜는 **yyyymmdd**.

## 1. 발급 정보

- 포털: **기상청 API 허브** https://apihub.kma.go.kr/
- 지상관측 > **기후통계** 카테고리에서 요소별로 **"활용신청"** 을 해야 열립니다(신청 즉시~수 분 내 승인).
- 이 프로젝트가 쓰는 활성화된 API: `sts_ta`(기온), `sts_cloud`(구름), `sts_rn`(강수량), `sts_sd`(적설), `sts_fog`(안개). (선택: `sts_ydst` 황사/PM10)
- **authKey:** `wiEQCJ__QkmhEAif_wJJtQ` (개인 발급. 배포 시 운영 계정 키로 교체)
- law.go.kr 의 `OC` 파라미터와는 다른 체계입니다. 기상 apihub 는 `authKey` 쿼리 파라미터를 씁니다.

## 2. 사용 API: 기후통계 일자료 (`sts_*`)

공통 형식:

```
GET https://apihub.kma.go.kr/api/typ01/url/{ep}.php
      ?tm1={시작}&tm2={종료}   # 일자료는 yyyymmdd (월자료 yyyymm, 연자료 yyyy)
      &stn_id={지점번호}        # 예: 203 (이천). 0=전체지점
      &disp=0                  # 0=빈칸없는 CSV, 1=등간격
      &help=0                  # 1이면 컬럼 설명 헤더 포함
      &authKey={authKey}
```

- 예시(이천, 2024-11-27):
  `https://apihub.kma.go.kr/api/typ01/url/sts_ta.php?tm1=20241127&tm2=20241127&stn_id=203&disp=0&help=0&authKey=wiEQCJ__QkmhEAif_wJJtQ`
- **장점:** 기간(tm1~tm2)을 한 번 호출하면 **일별 행 전체**가 온다. 날짜 수와 무관하게 요소별 1회 호출.

### 응답 포맷

- **인코딩: EUC-KR** (UTF-8 아님 → 서버에서 디코딩 필요)
- `#` 로 시작하는 줄은 주석/헤더, 그 외 한 줄이 하루치.
- `disp=0` 이면 **콤마 구분 CSV**. 결측값은 `-99.9`, `-999`, `-9`.
- 모든 행 공통 앞부분: `YMD(yyyymmdd), STN_ID, LAT, LON, ALTD, ...요소...`

### 요소별 컬럼 (0-based 인덱스, 콤마 split 기준)

| 엔드포인트 | 요소 | 쓰는 컬럼 | idx | 비고 |
| --- | --- | --- | ---: | --- |
| `sts_ta` | 기온 | **TA_DAVG** 일평균기온(℃) | 5 | 일 8회(03,06,…,24시) 평균 |
| | | TMX_DD 일최고(℃) | 6 | |
| | | TMN_DD 일최저(℃) | 8 | |
| `sts_cloud` | 구름 | **TCA_DAVG** 일평균전운량(0~10) | 6 | 맑음/흐림 판정 |
| `sts_rn` | 강수 | **RN_DSUM** 일합계강수량(mm) | 5 | 비 판정 |
| `sts_sd` | 적설 | **FSD_DMAX** 최심신적설(cm) | 5 | 눈 판정 (그날 새로 온 눈) |
| | | SD_DMAX 최심적설(cm) | 7 | |
| `sts_fog` | 안개 | **FOG_DUR_DSUM** 안개계속시간(h) | 5 | 안개 판정 |

> 전체 컬럼 정의는 각 URL에 `&help=1` 을 붙이면 응답 상단 주석에 나옵니다.

## 3. 날씨 산출 로직 (구현됨: `kma_proxy.py`의 `derive_weather`)

일 집계값으로 대표 날씨를 정합니다. 우선순위 위→아래:

```text
1) 눈:   신적설(FSD_DMAX) > 0            → "눈(NN cm)"
2) 비:   일강수량(RN_DSUM) > 0           → "비(NN mm)"
3) 안개: 안개계속시간(FOG_DUR_DSUM) > 0   → "안개"
4) 흐림: 평균전운량(TCA_DAVG) >= 6        → "흐림"
5) 맑음: 그 외                          → "맑음"
```

- 비/눈은 강수량과 적설량 수치도 함께 표기.
- 결측(-99.9/-999)은 판정에서 제외.
- 실측 검증: 서울(108) 2024-11-27 → `눈(19.3cm)`, 이천(203) 2024-12-02 → `맑음`(전운량 5.0), 2024-12-01 → `비(0.1mm)`.

## 4. 왜 프록시가 필요한가 (CORS)

- 기상청 apihub 응답에는 **`Access-Control-Allow-Origin` 헤더가 없습니다.**
- 따라서 브라우저(`index.html`)에서 `fetch()` 로 **직접 호출하면 CORS 정책에 막힙니다.**
- 해결: **프록시 한 겹.** 서버가 대신 KMA를 호출하고, 응답에 CORS 헤더를 붙여 브라우저에 돌려줍니다. (EUC-KR→UTF-8 변환도 서버에서 처리)

프로토타입은 이 역할을 **로컬 파이썬 프록시(`kma_proxy.py`)** 가 합니다. **배포 시에는 서버리스/서버 프록시로 이전**해야 합니다(§8).

## 5. 로컬 프록시: `kma_proxy.py`

```
실행:  python kma_proxy.py     →  http://127.0.0.1:8765
종료:  Ctrl+C
```

### 엔드포인트

```
GET /wx?stn=203&d1=2026-07-01&d2=2026-07-02     ← 날씨+온도 (요소 5개 호출)
GET /temp?stn=203&d1=2026-07-01&d2=2026-07-02   ← 온도만 (sts_ta 1회 호출)
```

`/wx` 응답(JSON, UTF-8, CORS 허용):

```json
{
  "ok": true,
  "stn": "108",
  "days": [
    {"date": "2024-11-27", "temp": -0.4, "tmax": 1.2, "tmin": -1.3,
     "weather": "눈(19.3cm)", "rain": 22.4, "snow": 19.3, "cloud": 9.1}
  ]
}
```

- `temp`=일평균기온, `tmax`/`tmin`=일최고/최저, `weather`=대표 날씨 문자열.
- 확정 전(최근 날짜) 등 데이터가 없으면 `temp`/`weather`가 `null`.
- 내부 상수: `AUTH`(authKey), `EP`(요소별 엔드포인트), `COL`(컬럼 인덱스), `PORT=8765`.

## 6. `index.html` 연동 방식

- ① 패널의 **「🌦 날씨/온도 자동 채우기」** 버튼(`#btnTemp`).
- 클릭 시 `fetch("http://127.0.0.1:8765/wx?stn=…&d1=…&d2=…")` → 결과를 전역
  `TEMPMAP = { "YYYY-MM-DD": 온도 }`, `WEATHERMAP = { "YYYY-MM-DD": "맑음" }` 에 저장.
- **「운영일지 생성」** 시 각 일자에 대해 `TEMPMAP`/`WEATHERMAP` 값이 있으면 폼의 `온도:`/`날씨:` 칸에 채웁니다.
- 프록시 미실행 시 상태줄에 연결 실패 안내 표시.
- 관련 상수: `const PROXY = 'http://127.0.0.1:8765';` → **배포 시 서버 프록시 URL로 교체.**

## 7. 기후통계 확정 지연 주의

기후통계는 재생산될 수 있고, **아주 최근 날짜(어제/오늘 등)는 통계가 확정되기 전이라 값이 비어 올 수 있습니다.** 운영일지가 보통 며칠~몇 주 지난 기록을 작성하는 경우가 많아 대개 문제되지 않지만, 결측이 오면 해당 일자의 온도와 날씨는 빈칸으로 두고 수동 입력하면 됩니다. (프록시는 결측을 `null`로 반환)
