# 날씨와 온도 연동 가이드 (기상청 apihub, 개발자 인수인계)

폐수배출시설 운영일지 생성기(`index.html`)의 **날씨와 온도 자동 채우기** 기능을 기상청 API와 연동하기 위한 문서입니다.
현재 프로토타입은 **온도**만 로컬 프록시로 연동돼 있고, **날씨(맑음/흐림/비/눈/안개)** 는 산출 로직만 설계된 상태입니다. 배포 시 개발자가 마무리해야 할 항목을 아래에 정리했습니다.

---

## 0. 요약 (TL;DR)

| 항목 | 현황 | 배포 시 할 일 |
|---|---|---|
| 온도 | 로컬 프록시(`kma_proxy.py`)로 동작 | **서버 프록시**로 이전 (Cloudflare Worker / Lambda 등) |
| 과거 기간 조회 | `kma_sfctm2` 특정시각 표본 8회 평균으로 우회 | `kma_sfctm3`(기간자료) **활용신청**하면 1회 호출로 대체 가능 |
| 날씨 산출 | 로직만 설계(아래 §8) | 실제 구현 + 폼 `날씨` 칸 채우기 |
| CORS | apihub는 CORS 헤더 없음 → 브라우저 직접 호출 불가 | 프록시 필수 (서버가 CORS 헤더 부여) |

- **인증키(authKey):** `wiEQCJ__QkmhEAif_wJJtQ`
- **관측지점:** 기본 `203`(이천). 드롭박스에서 60여 개 ASOS 지점 선택 가능.

## 1. 발급 정보

- 포털: **기상청 API 허브** https://apihub.kma.go.kr/
- 로그인 후 원하는 API마다 **"활용신청"** 을 해야 그 API가 열립니다(신청 즉시~수 분 내 승인).
  - 현재 승인된 것: `kma_sfctm2`(지상관측 시간자료, 특정시각)

- **authKey:** `wiEQCJ__QkmhEAif_wJJtQ` (이 계정에 종속. 배포 시 개발자/운영 계정 키로 교체 권장)
- law.go.kr 의 `OC` 파라미터와는 **다른 체계**입니다. 기상 apihub 는 `authKey` 쿼리 파라미터를 씁니다.

## 2. 사용 API: `kma_sfctm2` (지상관측 시간자료, 특정시각)

```
GET https://apihub.kma.go.kr/api/typ01/url/kma_sfctm2.php
      ?tm={YYYYMMDDHHMI}      # 관측시각 (KST), 분은 00
      &stn={지점번호}          # 예: 203 (이천)
      &help={0|1}             # 1이면 컬럼 설명 헤더 포함
      &authKey={authKey}
```

- 예시:
  `https://apihub.kma.go.kr/api/typ01/url/kma_sfctm2.php?tm=202607121400&stn=203&help=0&authKey=wiEQCJ__QkmhEAif_wJJtQ`
- **주의:** 이 엔드포인트는 **"특정 시각 스냅샷"** 용입니다. `tm1`/`tm2`(기간) 파라미터를 넣어도 **무시**하고 요청한 단일 시각(또는 최신값)만 돌려줍니다. → 하루/기간을 얻으려면 시각별로 여러 번 호출해야 함(§4, §6).

### 응답 포맷

- **인코딩: EUC-KR** (UTF-8 아님 → 서버에서 디코딩 필요)
- `#` 로 시작하는 줄은 주석/헤더, 그 외 한 줄이 한 관측레코드.
- 필드는 **공백으로 구분**된 고정폭. 결측값은 `-9`, `-9.0`, `-99.0`, `-`.
- `#START7777` 로 시작하고 `#7777END` 로 끝남.

### 주요 컬럼 (0-based 인덱스, 공백 split 기준)

| idx | 코드 | 의미 | 단위 | 비고 |
|----:|------|------|------|------|
| 0 | TM | 관측시각 | KST `YYYYMMDDHHMI` | |
| 1 | STN | 지점번호 | | |
| 11 | **TA** | **기온** | ℃ | ← 온도 연동에 사용 |
| 13 | HM | 상대습도 | % | 안개 판정 보조 |
| 15 | RN | 강수량 | mm | 4~10월 1시간, 11~3월 3시간 |
| 16 | RN_DAY | 일강수량 | mm | 해당시간까지 누적 |
| 20 | SD_DAY | 일 신적설 | cm | |
| 21 | SD_TOT | 적설(총) | cm | 눈 판정에 사용 |
| 24 | WW | 국내식 일기코드 | | 안개/강수 직접 표기(옵션) |
| 25 | **CA_TOT** | **전운량** | 1/10 (0~10) | 맑음/흐림 판정 |
| 32 | **VS** | **시정** | 10m 단위 | 예: `4893` = 48.93 km. 안개 판정 |
| 33 | SS | 일조 | hr | |

> 전체 46개 컬럼 정의는 `?help=1` 로 호출하면 응답 상단 주석에 나옵니다. (본 문서 작성 시 캡처본은 `kma_proxy.py` 주석과 이 표 참조)

## 3. TA(기온) 추출 예시

```python
raw = urllib.request.urlopen(url).read().decode("euc-kr", "replace")
for line in raw.splitlines():
    if not line or line.startswith("#"):
        continue
    f = line.split()
    if len(f) < 12:
        continue
    ta = float(f[11])        # 기온
    if ta <= -50:            # 결측(-9 등) 제외
        continue
    # ... ta 사용
```

## 4. 왜 프록시가 필요한가 (CORS)

- `kma_sfctm2` 응답에는 **`Access-Control-Allow-Origin` 헤더가 없습니다.**
- 따라서 브라우저(`index.html`)에서 `fetch()` 로 **직접 호출하면 CORS 정책에 막힙니다.**
- 해결: **프록시 한 겹.** 서버가 대신 KMA를 호출하고, 응답에 CORS 헤더를 붙여 브라우저에 돌려줍니다. (EUC-KR→UTF-8 변환도 서버에서 처리)

프로토타입은 이 역할을 **로컬 파이썬 프록시(`kma_proxy.py`)** 가 합니다. **배포 시에는 서버리스/서버 프록시로 이전**해야 합니다(§9).

## 5. `kma_sfctm2` 로 과거 기간을 얻는 방법 (표본 평균)

운영일지는 **과거 날짜** 기록입니다. 하지만:
- `kma_sfctm2` 는 기간(`tm1`/`tm2`)을 무시하고 단일/최신값만 반환.
- 기간자료용 `kma_sfctm3` 는 현재 authKey에서 **403(미활용신청)**.

→ 우회책: **하루를 3시간 간격 8개 시각(`00,03,06,09,12,15,18,21`)으로 각각 단일 `tm` 호출**해 TA 표본을 모으고 **평균**을 그 날의 일평균 온도로 씁니다. 최고/최저도 표본에서 산출.

- 장점: 현재 열려 있는 API만으로 과거 일평균/최고/최저 산출 가능.
- 단점: 하루당 8회 호출(N일 × 8). 30일이면 240회 → 서버 프록시에서는 캐싱 권장.
- **개선안:** `kma_sfctm3` 를 활용신청하면 `tm1~tm2` 한 번으로 시간자료 전체를 받아 평균 낼 수 있어 호출 수가 급감합니다.

## 6. 로컬 프록시: `kma_proxy.py`

```
실행:  python kma_proxy.py     →  http://127.0.0.1:8765
종료:  Ctrl+C
```

### 엔드포인트

```
GET /temp?stn=203&d1=2026-07-01&d2=2026-07-02
```

응답(JSON, UTF-8, CORS 허용):

```json
{
  "ok": true,
  "stn": "203",
  "days": [
    {"date": "2026-07-01", "temp": 25.7, "tmax": 29.1, "tmin": 21.7, "n": 8},
    {"date": "2026-07-02", "temp": 25.1, "tmax": 28.9, "tmin": 21.2, "n": 8}
  ]
}
```

- `temp` = 일평균(TA 표본 평균, 소수1), `tmax`/`tmin` = 표본 최고/최저, `n` = 유효 표본 수.
- 내부 상수: `AUTH`(authKey), `SAMPLE_HOURS=[0,3,6,9,12,15,18,21]`, `PORT=8765`.

## 7. `index.html` 연동 방식 (온도)

- ① 패널의 **「🌡 온도 자동 채우기」** 버튼(`#btnTemp`).
- 클릭 시 `fetch("http://127.0.0.1:8765/temp?stn=…&d1=…&d2=…")` 호출 → 결과를 전역 `TEMPMAP = { "YYYY-MM-DD": 온도 }` 에 저장.
- **「운영일지 생성」** 시 각 일자 `dstr` 에 대해 `TEMPMAP[dstr]` 이 있으면 폼의 `온도:` 칸에 채웁니다.
- 프록시 미실행 시 상태줄에 연결 실패 안내를 표시합니다.
- 관련 상수: `const PROXY = 'http://127.0.0.1:8765';` → **배포 시 서버 프록시 URL로 교체.**

## 8. 날씨(맑음/흐림/비/눈/안개) 산출: 설계(미구현)

현재 폼의 `날씨` 칸은 **비워둔 상태**(개발자 연동 예정)입니다. `kma_sfctm2` 한 레코드에서 아래 컬럼으로 산출할 수 있습니다.

사용 컬럼: `TA`(f[11], 기온), `RN`(f[15], 강수), `SD_TOT`(f[21], 적설), `CA_TOT`(f[25], 전운량 0~10), `VS`(f[32], 시정 10m단위), `HM`(f[13], 습도), (옵션) `WW`(f[24], 일기코드).

권장 판정 순서(우선순위 위→아래):

```
1) 눈:   SD_TOT > 0  또는 (RN > 0 그리고 TA <= 0)
2) 비:   RN > 0
3) 안개: VS < 100 (=1km 미만; VS는 10m 단위)  또는 WW에 안개코드  [보통 HM이 높음]
4) 흐림: CA_TOT >= 8      (구름많음 6~7, 흐림 8~10 로 세분 가능)
5) 맑음: 그 외 (CA_TOT <= 5)
```

- 하루 대표값을 쓰려면: 낮 시간대(예: 09,12,15시) 레코드로 판정하거나, 강수/적설은 일합계와 일신적설(`RN_DAY`/`SD_DAY`)을 쓰는 것이 안정적.
- 비/눈은 **강수량/적설량 수치**도 함께 표기 가능(요구사항이었음).
- 결측(`-9`,`-99`)은 판정에서 제외.

> 프록시에 `/weather?stn&d1&d2` 엔드포인트를 추가하고, 위 로직으로 하루 대표 날씨 문자열을 반환한 뒤, `index.html` 에서 온도와 동일하게 `WEATHERMAP` 에 담아 폼에 채우면 됩니다.
